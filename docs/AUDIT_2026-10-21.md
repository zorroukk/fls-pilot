# Fork audit sweep — 2026-10-21

This fork was deep-audited before being published as a standalone repository:
**six independent lanes**, each reading its subsystem end-to-end with a
bug-hunter's eye and proving every suspicion with a **red-first reproduction
script** before any fix. ~73 findings were raised; the critical and high
severity ones are fixed and covered by the regression tests in
`tests/test_audit_regression.py` + `tests/test_controller_guards.py`.

Method note: reproductions ran against the real code paths with fake FL/MIDI
surfaces (no FL Studio, no MIDI ports touched). The pre-existing suite (196
tests) can't see any of these — it never executes the controller script and
never drives the daemon's failure paths.

## Lanes

| lane | scope | headline results |
|---|---|---|
| D — daemon/transport | connection.py, daemon.py, protocol.py | phantom double-bind via `SO_REUSEADDR`; reader-thread death detected but never healed; interleaved chunk frames dropped by FL; "start the daemon" reported for a merely busy daemon |
| C — controller script | `fl_controller/…/device_FLStudioMCP.py` (2746 lines) | `-Infinity` dB from a zeroed fader escaped the handler guard (silent-death class); fabricated step reads became the rollback snapshot; writes used pattern-1 while reads used pattern; `midiNoteOn` got a local index where the manual says global; failed preview-note releases dropped silently; `OnDeInit` never released held notes |
| N — agent-facing contract | operations registry, safety layer, pyscript generation, `apply_notes` | the field piano-roll WIPE was still live in code (`params`-nested request → empty replace-mode script + hotkey, `ok:true`); raw note payloads unvalidated; `apply_notes` silently dropped notes when a transform was also present; dry-run retargeted the editor; non-ASCII marker names raised; rollback fired FL undo when nothing was applied |
| T — tools layer | pianoroll/channels/mixer/routing/transport/plugins/doctor | `fl_apply_bus_layout` accepted `bus_track=0` and emitted `src→Master ON` then `OFF` (killing sends, `ok:true`); `safe_write` reported success on writes FL never applied; snapshots fabricated read defaults; 4-beats-per-bar math ignored the project time signature; two competing norm→dB laws for the same value |
| R — publish readiness | music math, knowledgebase, packaging, docs | Mix Doctor mapped findings to tracks **by name** (duplicate names → wrong track trimmed twice, the other never); 10 "tests" were argv scripts hidden by an `--ignore` list and ran nowhere; installer hardcoded `%USERPROFILE%\Documents` (the exact ghost path the KB warns about); `.gitignore` missed the runtime-log trees full of absolute host paths; personal identifiers in tracked files |
| V — FL-version lock-in | every API the bridge uses, graded against the 326-page manual mirror | `fl_version` was computed and shipped but **never consumed** — no version handshake at all; README advertised "FL Studio 2025+" verified on a build this fork never ran; `set_time_sig` needs newer scripting APIs than the measured build; `midi.REC_Tempo` has zero manual coverage and was unguarded; `jumpToPattern(<0)` crashes FL 26.x (upstream's guard was not ported) |

## Fixed in this sweep (v2.1.0)

All critical/high findings plus most medium ones — see the v2.1.0 changelog
entry for the user-visible list. Every fix carries an inline comment naming
the audit id (`audit D2`, `audit N1`, …) so future readers can find the
mechanism and the reproduction.

## Reproductions

The original audit workspace (all ~40 reproduction scripts, each with its
observed RED output) is not part of this repository — it lived outside the
tree and referenced machine-local paths. The permanent, portable subset is
ported into `tests/test_audit_regression.py` (server/daemon/contract/tools)
and `tests/test_controller_guards.py` (controller script with fake FL
modules); both run in CI in seconds and fail loudly if any fixed defect
returns.
